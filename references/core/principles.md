# Testing Principles

The seven ISTQB testing principles, each with what it means for this skill.

1. **Testing shows the presence of defects, not their absence.**
   -> Never report "no bugs"; report what was covered and what was not.
2. **Exhaustive testing is impossible.**
   -> Prioritize by risk and stop when new scenarios stop changing the risk profile.
3. **Early testing saves time and money.**
   -> Review specs and discovery output for gaps before executing anything.
4. **Defects cluster together.**
   -> When one defect appears, probe the surrounding area before moving on.
5. **Tests wear out (pesticide paradox).**
   -> Vary inputs and routes between runs; don't repeat the same scenarios.
6. **Testing is context dependent.**
   -> Filter every technique through what discovery found about this app and its risks.
7. **Absence-of-defects fallacy.**
   -> A defect-free build that doesn't meet user needs still fails; check the oracle against real intent.
