## Executive summary

This is an unusually thorough, literature-faithful exploratory-QA methodology for
AI coding agents. Its strengths are oracle discipline (a 9-level hierarchy that
every technique cites), a real SBTM session mode, broad ISTQB CTFL coverage, and
agent-specific safety/honesty rules (allowlists, dry-run gates, `TEST_`-only data,
candidate-vs-confirmed labelling). The automated helpers (overlay + rapid-action)
are genuinely proven by self-tests that pass on local good/bad demo pages, and the
standalone agent builds and matches its documented suite counts.

Weaknesses are real but secondary: heavy token/context cost and redundancy across
30+ core files, a `PORTABLE.md` snapshot that is openly stale, full XSS/SQL
exploit payload lists still shipped in the lenses (behind an authorization banner)
which sits in slight tension with the "detection-only" framing, some Turkish-only
reference files, and unverifiable marketing anecdotes in the README. Nothing here
was exercised against a real production-like application in this review.

## Per-dimension justification

**A — Exploratory practice (5/5).** `references/core/session-mode.md` implements
SBTM faithfully: a three-part charter (`Keşfet / Şununla / Bulmak için`), a 60-min
timebox split into Test / Bug-investigation / Setup buckets recorded in minutes
(`templates/session-summary.md`), tagged notes (DENEDIM/BUG/SORU/FIKIR), explicit
exit criteria, and a backlog (`charters-backlog.md`, `diff-to-charter.md`).
Whittaker tours and Hendrickson-style heuristics are in
`heuristics-cheatsheet.md` (Tours §5, FEW HICCUPPS §1). The mandatory
"Kapsanmayan" (not-covered) line is a genuine debrief discipline.

**B — ISTQB CTFL v4.0 (5/5).** Seven principles verbatim with per-skill meaning
(`principles.md`); the full test process is covered across the phases plus
`planning-and-completion.md` (planning, monitoring/control with a budget-drop
order, completion/exit criteria, traceability table). Black-box techniques EP, BVA,
decision table, state transition, pairwise, use-case all in
`test-design-techniques.md` with an ISTQB cross-reference table; white-box appears
as a review lens; experience-based (error guessing, exploratory, checklist) and
collaboration-based (example mapping, ATDD/BDD) are present. Risk-based testing is
likelihood×impact with product-vs-project split (`risk-register.md`). The only
thin spot is the "test implementation" activity (environment/suite build), which
is implied rather than named.

**C — Oracles & heuristics (5/5).** `oracle-hierarchy.md` is a 9-level hierarchy
that is cited by essentially every other file, which is the backbone of the whole
skill. FEW HICCUPPS, SFDIPOT, CRUSSPIC STMPL (mapped to ISO 25010), and RCRCRC are
all in `heuristics-cheatsheet.md`. `metamorphic-differential.md` covers metamorphic
relations, differential/parity, and property-based testing (names `fast-check`,
shrinking, recording the seed). Exemplary.

**D — Risk-based prioritization & coverage reporting (4/5).** The risk register
(likelihood×impact levels, product/project tag, assumptions register that caps
oracle strength, heat-map) and the Phase-3 ordering wired to it are strong. The
report template surfaces risk ids and residual risk per id. Docked one point
because coverage reporting stays at the template level — there is no worked
coverage-metrics example beyond the scenario table, and no quantified coverage
model (e.g. which risks → which techniques → % executed) shown end to end.

**E — Defect handling (4/5).** `defect-classification.md` has a clear taxonomy,
impact-based severity rubric, and required fields; `second-opinion.md` handles
false-positive control (adversarial disprove pass, downgrade-only, count
downgrades), flakiness (reproduction rate must be stated, `FLAKY` label, no silent
drop), and duplicate merging. The Jira template has a strong worked example.
Docked one point because defect *isolation* (minimizing to a root-cause-bearing
repro, bisecting contributing factors) is only lightly implied, and duplicate
detection is prose guidance rather than a method.

**F — ISO/IEC 25010 & named standards (5/5).** CRUSSPIC STMPL is explicitly mapped
to ISO/IEC 25010 characteristics. WCAG 2.2 level AA is referenced by name with the
new-in-2.2 criteria called out (Focus Not Obscured, Target Size);
`web/accessibility-checks.md` gives concrete manual checks. OWASP WSTG / ASVS / API
Security Top 10 are named and correctly scoped to passive observation. Nielsen's 10
heuristics are listed with probes. Standards are cited by name only, never by
invented clause number — a deliberate, correct choice.

**G — Web/Mobile/API depth & AI-vs-human realism (4/5).** Web depth is excellent
(a11y, i18n, responsive, shadow DOM, XSS, six-directions). API is solid (lens,
authz matrix, three-witness, injection behind an authorization banner). Mobile is
good on the source-aware path (lifecycle, permission tri-state, deep links,
local↔server sync) but black-box mobile exploration is an *acknowledged* gap
(`blackbox-discovery.md` is web-only). AI-vs-human realism is honest (capability
boundaries, "Honest scope — what this does not do", the skill-vs-agent table).
Docked one point for the mobile black-box gap and because the mobile helpers are
guidance-only (no runnable mobile harness like the web ones).

**H — Agent-specific rigor (5/5).** Honesty about limits is baked in (candidate vs
confirmed, oracle level stated per finding, "say so explicitly" fallbacks).
Evidence-first is enforced (`evidence-capture.md`: a real saved file, not prose;
the actual first-run `console.log` gap is called out as the motivating failure).
Safety gates are concrete and layered: load `safety-gates.md` (7 ordered gates,
allowlist, `LOAD_WINDOW_OK`, dry-run), authz matrix dry-run-by-default + two-user
rule + env-var-only credentials, rapid-action burst caps, injection behind written
authorization. Data hygiene (`TEST_` only, existing data read-only, cleanup
verified) is repeated consistently. The helpers never throw and downgrade to
hints, which is the right posture for an agent.

**I — Usability for a human tester (3/5).** Good onboarding surface: README
"Start in 5 minutes", a prompts-that-work table, troubleshooting table, glossary.
But the context/token cost is high — `references/core/` alone is ~30 files, many
overlapping (`perturbation.md` vs `perturbation-dimensions.md` vs
`six-directions.md`; `advanced-exploratory-attacks.md` substantially duplicates
`input-mutation-catalog.md` and `test-design-techniques.md`). `SKILL.md` Phase 3
mandates reading *all* of `references/core/` before designing any test, which is a
large up-front load. Several reference files are Turkish-only
(`advanced-exploratory-attacks.md`, `session-mode.md`, parts of
`test-design-techniques.md`, the injection lens), which undercuts the
tool-neutral/portable claim for a non-Turkish reader. `PORTABLE.md` is openly a
stale snapshot. No hard contradictions remain, but the redundancy is a real cost.

## Remaining contradictions / over-claims

1. **"Playwright always installed/provisioned every run" (mandatory).** `SKILL.md`
   and `blackbox-discovery.md` use strong MUST/ALWAYS language. An AI agent cannot
   guarantee provisioning; the honest-scope paragraph partially walks it back, but
   the two framings coexist uneasily.
2. **"Active injection/XSS reduced to detection-only" is accurate for injection,
   overstated for XSS.** Verified: destructive SQL/XXE/path-traversal payloads are
   gone from the lenses (`grep -rniE "DROP TABLE|xp_cmdshell|pg_sleep|etc/passwd|UNION SELECT"
   references/lenses` → 0), and `backend-injection-testing.md` is genuinely
   reduced to a detection-only posture behind an authorization banner — that half
   of the claim is TRUE. But `references/lenses/web/xss-attack-patterns.md` still
   ships a full XSS payload catalog (script tags, event handlers, SVG vectors,
   filter-bypass encodings) behind the same banner; for XSS, "reduced to
   detection-only" overstates what the file contains (it is gated, not reduced).
3. **Turkish-only reference files vs. "tool-neutral, any agent" claim.** Several
   core/lens files are Turkish-only; a non-Turkish agent/reader loses content,
   which is in tension with the portability promise.
4. **`PORTABLE.md` drift.** Explicitly a stale snapshot (predates modes, lenses,
   packs, rapid-action, risk register). Honestly flagged, but it means two
   partly-divergent methodology documents ship together.
5. **Redundancy as a correctness risk.** Overlapping attack/mutation catalogs
   (`advanced-exploratory-attacks.md`, `input-mutation-catalog.md`,
   `test-design-techniques.md`, `six-directions.md`, `perturbation*.md`) can drift
   out of sync and inflate the mandatory read.

## What I verified by running commands (vs. only read)

All four commands ran locally on Node v22.20.0, Windows, with `agent/node_modules`
and `agent/dist` present and Playwright chromium installed.

- `node tools/lint-references.mjs` → `0 finding(s)`, exit 0. (No CJK leakage, no
  duplicate checklist lines — confirms the "corrupted characters removed" claim.)
- `npm --prefix agent run build` → `tsc` clean, exit 0. (Standalone agent compiles.)
- `node tools/selftest/run-selftest.mjs` → `SELFTEST PASSED`, exit 0. good-modal
  passes all automated OV checks; bad-modal correctly FAILS OV1, OV3, OV4, OV6,
  OV7, OV10. Observed output excerpt:
  `FAIL OV6 before=300 after=1100` (scroll-lock defect detected),
  `FAIL OV1 role=none aria-modal=null name=no`.
- `node tools/selftest/run-rapid-selftest.mjs` → `RAPID SELFTEST PASSED`, exit 0.
  Proven: good page = 1 request / 1 record per burst, guard within 150 ms, guard
  released; bad page = `MULTI_REQUEST+NO_UI_GUARD+NO_LOADING_INDICATOR+DUPLICATE_RECORDS`
  on bursts of 2 and 5, `SERVER_ERROR_5XX` on second delete, severity hint High;
  `maxTotalClicks=3` hard cap honored (`cap: total clicks 3, POSTs 3 (<= 3)`).

Everything else (methodology text, ISTQB/standards mapping, agent suite behaviour
beyond the two self-tests) was read, not executed.

## Honest limits of this review

- **Nothing was run against a real production-like application.** The self-tests
  exercise helpers on local static/served demo pages only; they prove the helpers'
  logic, not that the methodology finds real bugs in the field.
- **The standalone agent was built but not run against any live target**, so its
  real-world skip/finding behaviour (e.g. `skipped: no target element`) is read
  from code, not observed.
- **Marketing anecdotes are unverifiable from the repo**: the "production SaaS
  goal-tracking" frontend-only-validation find, the "five broken images with
  `alt=''`" dogfooding story, and "the self-test found and fixed two real helper
  bugs" have no in-repo evidence artifacts; they are claims, not verified facts.
- **What an AI agent cannot do reliably here**, regardless of how good the text is:
  guarantee tool provisioning/browser installation; reliably verify true
  persistence without DB access (API re-fetch can share the bug); judge weak-oracle
  findings without a human; maintain perfect data hygiene/cleanup on a shared env
  under failure; and reproduce timing-dependent races deterministically. The skill
  is honest about most of these, which is to its credit — but the scores above
  reflect documented coverage, not demonstrated field capability.
